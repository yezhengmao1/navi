# OKX 订单与交易复盘

## 执行流程

1. 将用户要求转换为下方 CLI 参数。默认从现在往回一个日历月（`1mo`），不是一月份或固定 30 天；月末对齐上个月最后一天，计算使用 UTC。
2. 从本 SKILL.md 的绝对路径解析相邻 `okx.py`，执行 `python3 <skill目录>/okx.py orders ... --json`。需要 Python 3.11+，无第三方依赖。
3. 默认报告同时执行 `python3 <skill目录>/okx.py account --json`，查询当前真实持仓和交易账户余额。用户只问当前持仓时仅执行 account，无需重查历史订单。account 不接受时间或产品筛选参数；输出包含查询时刻、positions、balances。两个接口不是原子快照；失败须明确报告，不得当作空仓。工具返回各状态订单；**展示和统计默认只用 `state == "filled"` 的订单**，排除撤单、未成交和部分成交。用户明确要求其他状态时才调整。筛选在结果处理层进行，不向 CLI 传不存在的状态参数。
4. 用完整的筛选结果计算汇总和复盘，再按下方格式展示；不要只统计展示出来的前几条。数值使用 Python `Decimal`，先计算后四舍五入，不用浮点数或心算汇总。
5. 失败或部分产品失败时报告失败，不将其当作无订单。结果太大时在本地解析完整输出后提取摘要，不从截断内容推算。仅修改展示格式可复用上次结果并注明未刷新；用户要求最新数据时重新查询。

只读查询，不下单、改单、撤单或操作资金。不自动推送、归档或同步账户数据。凭证缺失时只提示缺少字段与配置位置，不展示完整配置、不要求用户把真实密钥贴进对话。

## 参数映射

| 用户说法 | CLI 参数 |
|---|---|
| 看订单 / 最近一个月 | 不加时间参数，默认 `--since 1mo` |
| `~10h` / 最近 10 小时 | `--since '~10h'` |
| 最近 30 分钟 / 两周 / 30 天 / 两个月 | `--since 30m` / `2w` / `30d` / `2mo` |
| 北京时间某日起到某日整天 | `--start 'YYYY-MM-DDT00:00:00+08:00' --end '<末日次日>T00:00:00+08:00'` |
| BTC-USDT 现货 | `--inst-type SPOT --inst-id BTC-USDT` |
| 永续 / 交割合约 | `--inst-type SWAP` / `--inst-type FUTURES` |

- 时间按创建时间 `cTime` 筛选，区间为 `[start, end)`；不是成交时间或更新时间。`--end` 默认现在，显式时间必须带时区，不能与 `--since` 混用。
- 相对时间单位为 `m/h/d/w/mo`，可加 `~` 表示最近。日历月与 30 天不同。“今天/昨天”等日期查询需先明确用户时区；年份或时间范围有歧义时询问，不猜测。
- 默认查询 `SPOT/MARGIN/SWAP/FUTURES/OPTION`。`--inst-type` 可重复；`--inst-id` 需同时指定唯一产品类型。
- 自然语言由 skill 解释；脚本只接受确定性参数。不加 `--json` 是工具的原始表格输出，不是本 skill 的定制报告。

```bash
python3 <skill目录>/okx.py orders --json
python3 <skill目录>/okx.py orders --since '~10h' --json
python3 <skill目录>/okx.py orders --since 2w --inst-type SPOT --inst-id BTC-USDT --json
```

## 默认报告

按以下顺序输出中文报告，避免重复解释：

- **Markdown 加粗格式**：加粗短句的句末标点（如 `。`、`：`）放在结束标记 `**` 外，例如 `**盈利贡献集中**。9 月……`、`**核对完整成本**：优先……`。避免 `**盈利贡献集中。**9 月……` 这类结束标记前为标点、后紧接文字或数字的写法，以免 Pi 将其显示为原始星号。标题层级保持原样。

1. **范围**：账户实盘/模拟盘、完整查询区间及时区、产品、筛选后的已成交订单总数。没有符合条件的订单时到此结束，不编造复盘。
2. **买卖与剩余**：按产品分别展示 `🟢 买入 X`、`🔴 卖出 Y`、`📦 剩余多仓/空仓 Z`。买卖量汇总用 `accFillSz`，注明数量单位，不把合约张数写成币数。当前持仓必须使用 account 返回的最新数据，不用区间买卖差推算。展示所有非零持仓的产品、方向、数量、持仓均价、标记价格、浮动盈亏及其币种；可补充杠杆和保证金模式。合约 posSide=net 时按 pos 正负判多空，双向模式按 posSide 判断；合约数量为张，杠杆数量按接口单位。查询成功且无非零持仓时写“当前无合约／杠杆持仓”。现货展示交易账户币种现金余额 cashBal、可用 availBal、冻结 frozenBal，缺失值不当作零；小额币种保留精度。注明查询时刻、实盘／模拟盘及交易账户范围，不冒充资金账户或理财余额。查询失败才注明未获取及原因；不填造每笔历史交易后剩余量。
3. **盈亏汇总**：仅列“扣费前盈亏 / 扣费后盈亏”两项，**不单列手续费支出、手续费合计或返佣栏**。币种不同时分组，不能直接相加。
4. **成交明细**：默认展示最近 10 条，用户要求全部时展示全部；注明展示条数/总条数。所有行均已成交，不重复状态列。单一产品放标题，多产品增加产品列。默认不放订单 ID、委托量或“仅减仓/非减仓”等术语；排查具体订单时可补充 ID。
5. **交易复盘**：按下一节说明输出。

明细列固定为：

| 时间 | 买卖 / 开平 | 成交均价 | 扣费前盈亏 | 扣费后盈亏 |
|---|---|---:|---:|---:|

买卖栏使用 `🟢 买入 …` / `🔴 卖出 …`，把成交数量写在同一格。若能确认开平，写成“🟢 买入开多 X 张”“🔴 卖出平多 X 张”等；不能确认时只写“买入/卖出 X 张”，报告中统一说明开平未确认，不逐行堆砌术语。

### 开平判断

- 合约双向模式：`posSide=long` 时买入开多、卖出平多；`posSide=short` 时卖出开空、买入平空。
- 合约单向模式 `posSide=net`：`reduceOnly` 为 true（布尔或字符串）时，卖出为平多、买入为平空；其他订单需成交前持仓/成交过程才能确认，不能仅凭买卖方向、`pnl=0` 或 `reduceOnly=false` 断言开仓，可能涉及平仓或反手。
- 现货只写买入/卖出，不套用合约的做多做空标签。其他无法确定的产品同样保留买卖方向即可。

### 盈亏口径

- 单笔扣费前 = API `pnl`；单笔扣费后 = `pnl + fee + rebate`，保留 API 符号（负 fee 是支出，正 fee 是返费），不要再取绝对值相减。
- 仅在盈亏、手续费、返佣计价币种一致且可确认时计算扣费后值；不能仅由交易对名称猜测所有产品的结算币种。必要字段缺失或币种无法确认时标注“无法计算”，不要把缺失值当零或把不完整小计称为总收益。
- 汇总按相同口径累加**全部筛选后的订单**。展示一般保留两位小数，极小金额应增加精度避免显示成零；价格保留足以区分成交价的精度。
- 报告只需一次简短说明：扣费后仅计所列订单的手续费及返佣，未计资金费、浮动盈亏或区间外成本，**不是账户完整净收益**；单笔扣费后也不等于完整开平仓净收益。`pnl=0` 不代表持仓没有浮盈亏。
- 现货等订单的 `pnl` 不足以表示交易利润时，明确该字段的局限，不把零值解读为实际不赚不亏。

## 交易复盘

不是重复汇总数字或给出买卖建议。用订单事实复盘交易执行，结构为：

1. **✅ 做单优势**：列出有数据支持的优点及典型订单，例如持有有效波段、分批退出。只有一次案例就说一次，不升级为稳定能力；分批退出本身不等于执行更优。
2. **⚠️ 做单劣势**：分析利润集中、亏损集中、短线成本侵蚀、频繁切换或交易规模变化。引用具体时间、数量和扣费前后盈亏；不单列手续费金额。没有计划和持仓过程，不断言扛单、情绪化、过度杠杆或违反止损纪律。
3. **🔍 典型交易**：选择 1–2 个有代表性的案例解释得失，可并入优势/劣势以避免重复。数量与时间接近只能提示可能对应，未经持仓/成交流水核实必须写“若为同一轮交易”；不能据此确认为开平配对、持仓时长或整轮收益。
4. **📌 改进动作**：提出与上述证据对应的复盘动作，例如分开统计波段与短线、记录计划与实际退出、核对毛利为正但扣费后为负的交易。不给行情预测或具体下单建议。

只写有依据的结论，数据不足直接说明。减仓订单盈利占比不能称为完整交易胜率；缺少权益、资金费和持仓过程时，不计算账户收益率、最大回撤或仓位风险。跨产品数量不可相加用于评价仓位大小。

## 配置与安全

凭证统一放 **`~/.navi/config.toml`**，合并配置，不覆盖其他段或重复添加 `[okx]`：

```toml
[okx]
api_key = "YOUR_OKX_API_KEY"
secret_key = "YOUR_OKX_SECRET_KEY"
passphrase = "YOUR_OKX_API_PASSPHRASE"
base_url = "https://www.okx.com" # 可选，默认值
simulated = false               # true 为模拟盘，需对应密钥
```

- Passphrase 是创建 API Key 时的口令，不是登录密码。建议只授予 Read 权限、绑定出口 IP，并 `chmod 600 ~/.navi/config.toml`；脚本不能核验密钥实际权限。
- 密钥不得进入 CLI 参数、仓库、日志或对话输出。只接受官方 HTTPS 地址 `https://www.okx.com`、`https://us.okx.com`、`https://eea.okx.com`，禁用重定向。
- Navi `sync` 会备份整个 `~/.navi`，包括 OKX 密钥；保护 WebDAV 备份，查询流程不主动同步。

## 工具覆盖与验证

- `account` 仅 GET 查询 `/api/v5/account/positions` 和 `/api/v5/account/balance`，获取当前持仓及交易账户余额；仍不提供历史持仓、资金账户余额或完整资金流水。
- 订单仅 GET 查询 `orders-pending`、`orders-history-archive`（近 3 个月）、`orders-history`（近 7 天）；按 `after=ordId` 翻页，按产品类型/订单 ID 去重并保留较新 `uTime`，创建时间倒序输出。多页查询不是一致性快照。
- 支持常规订单字段层面的盈亏汇总；**不提供**逐笔 fills、历史持仓、资金流水、账户完整收益或尚未转为常规订单的算法委托。不要用订单列表冒充这些数据。
- 查询起点超过近 3 个月会报错，应从 OKX 导出历史记录。未成交即撤销订单通常只保留 2 小时；仅展示已成交时无需重复撤单保留说明，但不能承诺返回所有历史记录。
- HTTP 429/5xx、网络错误及 API 限流码 50011 有有限重试。鉴权失败检查凭证、IP 白名单、地区、模拟盘配置与时钟，不回显鉴权头。
- 官方文档：<https://www.okx.com/docs-v5/en/#order-book-trading-trade>。
